Streaming /mipmap/64 → WebGL2

On startup, this page requests up to 100 items from the library. Each run posts that same comma-separated list of image IDs to /mipmap/64 and feeds its response stream directly to ImageDecoder. Complete frames are decoded, uploaded, and drawn while the download continues. Mipmap network time is included; the initial library request is not.

Texture arrays are allocated in batches as frames arrive; the client does not wait for the final frame count. The preview has 100 fixed slots in a 10×10 grid backed by a persistent GPU thumbnail cache keyed by the requested image IDs.

One warmup is excluded. Each run uses a fresh high-priority fetch with cache: no-store. WebGL initialization is outside the measured runs. Decode waits include waiting for incoming bytes. The preview redraws all loaded visible slots on requestAnimationFrame when thumbnails arrive, the view resizes, or a run requests a draw. It uses the default non-preserved drawing buffer and linearly filtered cached textures. The first upload of each thumbnail is retained for the preview; subsequent runs still decode and upload fresh textures to measure cold processing, then release those temporary textures. GPU mipmap generation is measured after all frames arrive. Upload and draw timings measure CPU submission, not presentation or GPU execution. GPU-complete includes a fence after final mipmaps and drawing; polling adds latency. No gl.finish() in the measured path.

Serve this directory over localhost; ImageDecoder requires a supported browser and secure context.
