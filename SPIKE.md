# Tauri spike

Goal: ship booru as a small native desktop app. The UI is the existing
server-rendered HTML + htmx served by the Odin server; the window is a system
webview pointed at it.

## What it is

`spike/tauri/` is a minimal Tauri 2 app. `src/main.rs` opens one window on an
external URL (default `http://127.0.0.1:8080/`, or the first CLI argument).
There is no frontend bundle: `dist/index.html` is a stub that satisfies
`build.frontendDist`.

- The Odin server stays a separate process. Start it first.
- `icons/icon.png` is a 64x64 placeholder. `generate_context!()` fails without it.
- `[profile.release]` is size-tuned: `opt-level = "s"`, LTO, `codegen-units = 1`,
  `panic = "abort"`, `strip = true`.

## Build and run

Linux prerequisites (Debian/Devuan package names):

    sudo apt install build-essential pkg-config libwebkit2gtk-4.1-dev \
        libgtk-3-dev libsoup-3.0-dev libssl-dev

Tauri 2 / wry 0.57 need GTK3 and `webkit2gtk-4.1`. A machine with only GTK4 /
WebKitGTK 6.0 dev files fails in `gdk-sys` / `atk-sys` with
`Package gdk-3.0 was not found`.

    ./bin/booru -port:8080 -library:<path>     # from the repo root
    cd spike/tauri
    cargo build --release
    ./target/release/booru-tauri-spike [url]

Release build took about 37 s after dependencies were fetched.

## Results

- Release binary: **3.3 MB** (stripped, size profile above).
- Dynamically links the system `libwebkit2gtk-4.1`, `libgtk-3` and `libsoup-3.0`
  (171 shared libraries in total, via `ldd`).
- htmx, the inspector and the tag-edit popover work unchanged in the window
  (WebKitGTK implements the Popover API). No shims, proxy or app changes were
  needed. Confirmed by eye on Linux; there was no automated check.

## Caveats

- Not self-contained: the target machine needs WebKitGTK 4.1. A binary built
  against 4.1 will not run where only the 6.0 stack is installed.
- Two processes: nothing starts or stops the Odin server. A real version would
  spawn it (Tauri sidecar) and shut it down on exit, and pick a free port.
- Linux only so far. Windows (WebView2) and macOS (WKWebView) use different
  engines and are untested. `src/daemon_windows.odin` suggests Windows matters.
- The 3.3 MB excludes the Odin binary (1.3 MB) and `static/` (about 676 KB).
- No packaging (`bundle.active` is false), signing, window state, or error
  handling when the server is not up.
- `gen/` is generated by `tauri-build` and is gitignored.
